ascii-tabs

A zero-dependency web component to write and show guitar tabs as plain ASCII. Every section shows a feature off and on, one variant after the other, each with its code a click away.

Bare <ascii-tabs> is editable. readonly shows only copy on each Sheet.

Keyboard shortcuts

Click a String to place the cursor, then use these shortcuts in any editable Tab. Drag from an empty cell or blank Sheet area to select notes, then drag any selected note to move the group. Cmd is the Command key on macOS; Alt is also called Option.

KeyAction
0–9Type a fret number from 0 to 24 in the current cell.
Left Arrow / Right ArrowMove to the previous or next Column.
Up Arrow / Down ArrowMove between Strings, crossing into the adjacent Staff at its edge.
Enter / TabMove to the next Column. Hold Shift to move to the previous Column.
Cmd + Right Arrow
Alt + Right Arrow		Duplicate selected notes as a group after its last Column and select the duplicate. Without a selection, copy all six Strings of the current Column into the next one, replacing its contents. Extends the Tab when needed.
Cmd/Ctrl + CCopy selected notes as ASCII. The Sheet's copy button also copies the selection.
Cmd/Ctrl + VPaste ASCII at the current Column, keeping its String positions.
Cmd + 0
Alt + 0		Fill only the empty cells of the current Column with zeros. Keep existing frets and the cursor in place.
BackspaceRemove selected notes, or remove the last digit from the current fret.
DeleteRemove selected notes, or clear the current cell.
EscapeClear the selection, or cancel the current typing and restore the cell's previous value.

Initial value

Prefer passing the content as data through the value property: an array of Tabs, each an array of Columns, each Column 6 entries from String 1 to String 6, a Fret (0–24) or null. It is the same shape value and change give back. If all you have is ASCII text, a <pre> per Tab works too; number labels and note labels both parse, with any number of dashes.

From data (preferred)

Aligning with a score

When a score renderer controls horizontal spacing, supply columnLayout: one { width, positions } per Tab. Each positions[c] is the center of Column c in CSS pixels from the left edge of the String area (.ascii-tabs-area). Labels, Sheet padding and tools sit outside those coordinates. Align that area's origin with the score's origin and convert the score's coordinates to CSS pixels.

Each Tab stays in a single Staff with six full-width Strings and horizontal scrolling when needed. One- and two-digit Frets, note names and parentheses share the supplied centers. Spacing affects ASCII copy, while the screen follows the external positions.

External positions (editable)

const editor = document.getElementById('alignment-demo');
editor.setDocument({
  value: [[
    [5, 7, null, null, null, null],
    [null, null, null, null, 0, null],
    [12, null, null, null, null, null],
    [null, null, null, null, null, null],
  ]],
  columnLayout: [{ width: 640, positions: [84.5, 132, 201.25, 290] }],
});

// Geometry-only updates keep the cursor and typing in progress.
editor.columnLayout = [{ width: 640, positions: [84.5, 140, 220, 320] }];

editor.addEventListener('layoutoverflow', ({ detail }) => {
  // { index, width, collisions }
  // A collision has zero-based string and columns indices, overlap in CSS
  // pixels, and an optional edge: 'left' or 'right'.
  console.log(detail);
});

// Restore automatic ASCII layout, wrapping and padding.
editor.columnLayout = null;

External layout: four fixed Columns, including the empty final Column. Click a String to edit.

width must be finite and positive; positions must be finite, strictly increasing, within [0, width], and match every logical Column, including empty trailing Columns. A zero-Column Tab uses positions: [] and still displays six Strings. Invalid layouts throw a descriptive TypeError before changing state. Geometry is copied on assignment and retrieval.

Use setDocument({ value, columnLayout }) to change content and positions atomically. Assign columnLayout alone to reposition existing Columns; assigning value while a layout is active requires the same Tab and Column counts. Programmatic updates do not emit change. Both value and change.detail.value preserve trailing empty Columns in this mode. Geometry stays outside Tab[].

Keyboard editing, mobile input, selection, dragging and duplication work within the existing Columns. Clicks and drops use the nearest center; exact ties choose the earlier Column. Navigation stops at the ends. Paste, duplication and group moves that exceed the available Columns are rejected in full. Deleting a Fret empties its cell. Add/delete Tab buttons are disabled and addTab()/removeTab() do nothing; the consumer changes structure through setDocument().

layoutoverflow bubbles after rendering if Frets collide on the same String or cross the area's edges. Repeated identical reports are suppressed until geometry or collisions change. The editor keeps the centers fixed: recalculate the score spacing and provide new positions as well as a new width. Increasing the width alone cannot separate existing centers. Set --ascii-tabs-fret-background to match the surface behind the Frets when embedding on a custom background.

Built-in storage is suspended while external geometry is active; the consumer owns persistence. Copy still exports ordinary ASCII through format(), without pixel positions or trailing empty Columns. columnLayout = null restores automatic ASCII layout and storage; setDocument({ value }) also selects ASCII layout.

Per-note colors and bold

With structured value data, replace a fret number with { fret: 3, color: '#b91c1c' } to give that note its own CSS color. Numbers keep the default color; omitted or invalid colors fall back to it. CSS variables such as var(--melody-color) work too.

Set bold: true for bold text or bold: false for normal weight. Omit it to keep the existing bold default. Combine it with color or use it alone; font weight follows the note through edits, moves, duplicates and storage, and is discarded when copying ASCII.

The color follows the note through edits, moves, duplicates, change events and storage. ASCII input has no color information, and copying exports plain text without colors.

Colored melody (editable)

Note notation

Choose fret numbers, letters (E D F) or lowercase Spanish notes (mi re fa). Open String 1 is E / mi in standard tuning. Columns grow to fit names such as sol#, keeping all six Strings aligned. Keep typing fret numbers to edit; copying uses the selected notation. To paste the result back, copy in fret numbers.

AttributeDisplayed cells
notation="frets" (default)Fret numbers, 0–24
notation="letters"C D E F G A B
notation="solfege"do re mi fa sol la si

Notes follow standard tuning, String 1 to 6: E B G D A E. Accidentals use sharps (F#, fa#), and octaves share the same name: Frets 0, 12 and 24 on String 1 all display E / mi. Import and paste accept numeric tablature only.

Add <ascii-tabs-notation> for the optional selector, including in read-only mode. The notation property and format(tab, { notation: 'solfege' }) use the same options. lang controls interface language and labels controls String labels independently. Editing, value, storage and change preserve the original Frets.

Column annotations

Attach text or HTML to logical Columns with annotations: one array per Tab of { column, text } or { column, html, text? } entries (indices start at zero). Change the Spacing slider or resize the page: annotations follow their Columns across Staves. Colliding content stacks above the Strings with enough room to avoid overlap.

This is optional: without annotations, the existing layout and editing stay the same. Each anchor must reference an existing Column in value, including explicitly supplied empty Columns. text is literal and supports newlines; html renders markup such as <strong>, <sup> and <br>. HTML is inserted as supplied: use trusted or sanitized markup. Size changes in normal flow HTML, such as loaded images, update the reserved space. Update content with element.annotations = [[{ column: 1, html: '<strong>Dm</strong>' }]], or clear it with element.annotations = null. Moving Frets leaves annotations attached to their original Columns.

With both fields, html controls the display and text supplies the ASCII fallback. Browser copy extracts text from HTML when no fallback is supplied, preserving line breaks. Calling format() outside a browser requires the text fallback for HTML annotations.

setDocument({ value, annotations, columnLayout }) validates and updates the document together; omitting annotations clears them. Setting value alone preserves existing annotations and requires their anchors to remain valid. Keep annotations in your own state for persistence; built-in storage contains notes. Whole-Tab copy includes aligned annotations; selected-note copy keeps the usual ASCII. To import copied text, remove annotation lines first.

Enable annotations-editable and titles-editable independently. Hover a Column to reveal a horizontal bar; click the strip above its Strings to write. Hover above the card’s upper-left corner to add a title outside the card. Click existing text to edit it. The borderless editor has a subtle bottom line: Enter or blur saves, Escape cancels, Shift+Enter adds a newline. Tab then Enter or Space also opens a target. readonly disables editing.

Set titles with element.tabTitles = ['Estudio'], or include tabTitles in setDocument(). Listen for annotationchange ({ index, column, annotations }) and titlechange ({ index, title, tabTitles }) to persist user changes. Programmatic assignments are silent. Titles are separate from ASCII export and built-in note storage.

Chord annotations

const chords = document.getElementById('annotations-demo');
chords.annotationsEditable = true;
chords.titlesEditable = true;
chords.setDocument({
  tabTitles: ['Estudio'],
  value: [[
    [null, null, null, null, null, null],
    [1, 3, 2, 0, null, null],
    [1, 3, 2, 3, null, null],
    [1, 3, 2, null, 0, null],
  ]],
  annotations: [[
    { column: 0, text: 'RE MENOR' },
    { column: 1, html: '<strong>Dm</strong><sup>*</sup>', text: 'Dm*' },

Storage

Opt-in persistence. <ascii-tabs-storage key="…"> loads the Tabs from localStorage under that key on start and saves them on every change; stored content wins over an initial value and <pre>. Without the part nothing is stored. Type something and reload this page.

value and change

Read and write value; every edit fires change. The component is uncontrolled by default. For the controlled pattern, keep the Tabs in your own state: update it on change and write value back when the state changes elsewhere. Edit the Tab or the JSON below; each one updates the other.

let state = [[]];
const tabs = document.getElementById('json-demo');
const json = document.getElementById('json');

// Component → state
tabs.addEventListener('change', e => {
  state = e.detail.value;
  json.value = JSON.stringify(state);
});

// State → component
json.addEventListener('input', () => {
  try { state = JSON.parse(json.value); } catch { return; }
  tabs.value = state;
});
